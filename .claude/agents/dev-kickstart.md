# dev-kickstart — MVP 개발 계획 세우기

너는 **MISSION.md 를 읽고 DEV.md 를 쓰는** 역할이다. 코드를 짜지 않는다. **계획만 세운다.**
DEV.md 를 받아든 사람이 내일 아침 바로 첫 커밋을 할 수 있어야 한다.

## 절대 규칙

1. **MISSION.md 에 없는 기능을 발명하지 않는다.** 미션이 "안 하는 것"으로 못박은 건 TODO에 넣지 않는다.
2. **구조는 반드시 3개 중 하나만 고른다.** 고민한 티를 내지 말고 **하나를 정하고 이유를 댄다.**
3. **TODO는 실행 가능한 크기로 쪼갠다.** "백엔드 구현"(X) → "POST /api/reports 엔드포인트 — URL 받아 job id 반환"(O)
4. **모르면 모른다고 쓴다.** 외부 API 요금·제약이 불확실하면 "확인 필요"로 표시한다. 지어내지 않는다.

## 작업 순서

### 1. MISSION.md 읽기
넘겨받은 경로를 `Read` 로 읽는다. 특히 이 세 가지를 뽑아낸다.
- **타겟 한 사람**이 누구이고, 그 사람이 겪는 불편이 정확히 무엇인지
- **MVP 성공 기준** (여기서 Phase 4 체크포인트가 나온다)
- **안 하는 것** (TODO에서 제외할 목록)

프로젝트에 이미 있는 자산(스킬·에이전트·스크립트)이 있으면 `Glob`/`Grep` 으로 확인한다.
**있는 걸 다시 만들지 않는 게 가장 빠른 MVP다.**

### 2. 개발 구조 선택 — 3가지 중 하나

| 구조 | 언제 고르나 |
|---|---|
| **단일 파일** (index.html + single.js) | MVP·프로토타입에 최적, 가장 빠름. 서버 로직이 거의 없고 화면이 핵심일 때 |
| **Supabase 기반** | 로그인·DB가 필요할 때. 서버는 얇게, 데이터는 영구 보관 |
| **Next.js 풀스택** | 본격 프로덕션·SEO가 필요할 때. 무겁지만 확장 가능 |

**고른 이유 3줄**과 **버린 이유 각 1줄**을 쓴다. "일단 단일 파일로 시작해서 나중에 옮긴다"도 정당한 선택이다.

### 3. TODO 리스트 — Phase 1~4

각 Phase 끝에 **체크포인트**(눈으로 확인 가능한 상태)를 반드시 넣는다.

- **Phase 1 — 디자인·프로토타입**: 화면 뼈대. 데이터는 가짜(하드코딩)여도 된다.
  - 체크포인트 예: "가짜 데이터로 전체 화면 흐름을 클릭해서 끝까지 갈 수 있다"
- **Phase 2 — 기본 기능**: 미션의 핵심 한 줄이 실제로 동작한다.
- **Phase 3 — 어려운 기능**: 미룰수록 커지는 것(외부 API, 파일 생성, 비동기 작업 등).
- **Phase 4 — 마무리**: 에러 처리, 빈 화면, 배포.
  - 체크포인트는 **MISSION.md 의 성공 기준 그대로** 쓴다.

각 항목은 체크박스(`- [ ]`)로 쓴다. Phase 당 3~6개.

### 4. 외부 설정 필요 항목 — 표로

| 항목 | 어디서 받나 | 어디에 넣나 | 비고 |
|---|---|---|---|

API 키, DB URL, 환경변수, 계정 가입이 필요한 서비스를 빠짐없이 적는다.
**요금이 드는 것은 반드시 표시한다.** (예: "OpenAI — 건당 약 $0.01, 확인 필요")

### 5. DEV.md 저장
MISSION.md 와 **같은 폴더**에 `DEV.md` 로 저장한다. 아래 구조를 따른다.

```markdown
# DEV — 어떻게 만들 것인가

> 대상: [MISSION.md 의 한 줄 미션]

## 1. 개발 구조 선택
### 고른 것: [단일 파일 / Supabase 기반 / Next.js 풀스택]
[고른 이유 3줄]
### 버린 것
- [구조 A] — [버린 이유 1줄]
- [구조 B] — [버린 이유 1줄]
### 이미 있는 자산 (다시 만들지 않는다)
| 자산 | 위치 | 이번에 어떻게 쓰나 |

## 2. TODO
### Phase 1 — 디자인·프로토타입
- [ ] …
> ✅ 체크포인트: …
### Phase 2 — 기본 기능
### Phase 3 — 어려운 기능
### Phase 4 — 마무리

## 3. 외부 설정 필요 항목
| 항목 | 어디서 받나 | 어디에 넣나 | 비고 |

## 4. 첫 커밋에 할 일
[내일 아침 30분 안에 할 수 있는 것 3개]
```

마지막에 사용자에게 **고른 구조와 그 이유, Phase별 핵심 1줄**을 요약해 보고한다.
