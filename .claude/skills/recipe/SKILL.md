# Recipe (재료 기반 레시피 추천 + 마크다운 저장)

`week_4/퀘스트1` 폴더의 재료 JSON 파일을 읽어, 실제 영양 정보와 보유 재료를 바탕으로
요리 레시피를 추천/생성하고 **결과를 마크다운 파일로 저장한다.**

## 재료 데이터 위치

- 폴더: `week_4/퀘스트1/`
- 파일: `egg.json`, `vegetable.json`, `meat.json`, `cheese.json` (그 외 `*.json`도 모두 포함)
- 각 파일 스키마(예시):
  ```json
  {
    "name": "egg",
    "nameKo": "달걀",
    "category": "단백질",
    "description": "...",
    "examples": ["소고기", "돼지고기"],
    "servingSize": "100g",
    "nutritionPer100g": { "calories_kcal": 143, "protein_g": 12.6, "fat_g": 9.5, "...": 0 },
    "keyNutrients": ["..."],
    "storage": "...",
    "shelfLifeDays": 30
  }
  ```

## 절차

1. **재료 로드**: `week_4/퀘스트1/` 폴더의 모든 `*.json` 파일을 Glob으로 찾고 Read로 읽는다.
   각 파일의 `nameKo`, `category`, `examples`, `nutritionPer100g`, `keyNutrients`를 파싱한다.
   폴더가 비어 있거나 파일이 없으면 사용자에게 알리고, 재료를 직접 입력받는다.

2. **사용자 조건 확인**: 슬래시 명령 뒤 인자나 대화에서 조건을 반영한다.
   - 사용할 재료 지정 (예: `/recipe 계란 치즈`) → 해당 파일만 사용
   - 제약: 조리 시간, 인분 수, 저칼로리/고단백 등 목표
   - 없으면 폴더의 전체 재료를 활용한다고 가정한다.

3. **레시피 1~3개 생성**: 보유 재료 조합으로 만들 수 있는 현실적인 요리를 만든다.
   각 레시피는 아래 형식을 지킨다.

   ```
   ## 🍳 {요리 이름}
   - 소요 시간 / 난이도 / 인분
   - 사용 재료: (폴더 재료는 ✅ 표시, 추가로 필요한 재료는 별도 표시)
   - 재료별 분량
   - 조리 순서 (번호 목록, 3~7단계)
   - 예상 영양(1인분): 칼로리 / 단백질 / 지방 / 탄수화물
   - 한 줄 팁
   ```

4. **영양 계산**: `nutritionPer100g` × (사용 g수 / 100)으로 합산해 1인분 기준으로 나눈다.
   추정값임을 명시하고 소수점은 1자리로 반올림한다.

5. **마크다운 파일 저장 (필수)**: 생성한 레시피를 항상 파일로 저장한다.
   - 저장 폴더: `week_4/퀘스트1/recipes/` (없으면 Write로 파일 생성 시 자동 생성됨)
   - 파일명: 레시피가 1개면 `{요리이름}.md`, 여러 개면 하나의 파일
     `recipe-{YYYY-MM-DD}.md`에 모두 담거나 각 요리별로 나눠 저장한다.
   - 파일 상단에 생성일, 사용한 재료 목록을 머리말로 넣는다.
   - 저장 후 저장된 파일 경로를 사용자에게 알려준다.

## 원칙

- 폴더의 실제 재료와 영양 데이터를 우선 근거로 삼는다. 데이터에 없는 값은 추정임을 밝힌다.
- 소금·후추·기름·물 같은 기본 조미료는 보유한 것으로 간주해도 된다.
- 요리 이름과 설명은 한국어로 제공한다.
- 재료가 부족해 조합이 빈약하면, 최소 추가 구매 목록을 함께 제안한다.
- 저장은 요청 없이도 항상 수행한다(이 스킬의 핵심 동작). 채팅에도 레시피 전문을 함께 출력한다.
