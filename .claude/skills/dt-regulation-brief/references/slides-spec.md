# slides.json 스펙 — 슬라이드 디자이너 → 렌더러 핸드오프 계약

슬라이드 디자이너 에이전트는 **`.pptx`를 직접 만들지 않는다.** 이 스키마대로 `slides.json`만 쓰고,
실제 렌더링은 `scripts/render_ppt.py`(python-pptx)가 한다. 덕분에 매번 같은 품질·같은 브랜드로 나온다.

## 전체 구조

```json
{
  "title": "전자금융거래법 개정 — DT본부장 검토",
  "subtitle": "이사회 보고자료",
  "date": "2026-07-14",
  "author": "DT본부",
  "slides": [ /* 아래 슬라이드 객체들 */ ]
}
```

## 슬라이드 타입 5종

렌더러가 지원하는 레이아웃은 이 5개뿐이다. **없는 타입을 지어내지 않는다.**

### 1) `bullets` — 가장 많이 쓰는 기본형

```json
{
  "type": "bullets",
  "title": "사안 요약",
  "bullets": [
    "2027년 1월 시행 — 준비기간 18개월",
    { "text": "적용 대상: 전자금융업자 전체", "sub": ["우리 은행 포함", "자회사 2곳 별도 등록 필요"] }
  ],
  "note": "발표자 노트 (선택)"
}
```
- 불릿은 문자열 또는 `{text, sub[]}` 객체. **한 슬라이드에 최대 6개**, 한 줄 40자 이내.

### 2) `table` — 법령 매핑·실행과제처럼 열이 있는 것

```json
{
  "type": "table",
  "title": "관련 법령 매핑",
  "headers": ["자료", "핵심 조항", "우리 기관 관련성"],
  "rows": [
    ["전자금융감독규정", "제13조 접근매체", "인증 체계 재설계 필요"],
    ["신용정보법", "제32조", "동의 절차 변경"]
  ]
}
```
- **최대 6행**. 넘으면 슬라이드를 나눈다. 셀은 짧게(20자 이내).

### 3) `chart` — 숫자를 보여줄 때 (PowerPoint 네이티브 차트, 편집 가능)

```json
{
  "type": "chart",
  "title": "규제 대응 예상 비용",
  "chart": "bar",
  "categories": ["인증체계", "로그·감사", "외부점검"],
  "series": [ { "name": "예상 비용(억원)", "values": [12, 5, 3] } ],
  "insight": "인증체계 개편이 전체 비용의 60%를 차지한다"
}
```
- `chart`: `"bar"` | `"column"` | `"line"` | `"pie"` 중 하나.
- `insight`: 차트 아래 한 줄 해석. **차트만 두고 해석을 빼지 않는다.**

### 4) `timeline` — 시행 일정·마일스톤

```json
{
  "type": "timeline",
  "title": "대응 로드맵",
  "items": [
    { "when": "2026 Q3", "what": "영향도 분석 완료" },
    { "when": "2026 Q4", "what": "시스템 설계·예산 확보" },
    { "when": "2027.01", "what": "규제 시행" }
  ]
}
```
- **최대 5개**.

### 5) `action` — 즉시 액션 아이템 (보통 마지막 슬라이드)

```json
{
  "type": "action",
  "title": "즉시 액션 (Top 3)",
  "actions": [
    { "what": "인증체계 영향도 TF 구성", "who": "디지털개발부", "when": "7월 내" },
    { "what": "감독당국 사전 협의", "who": "준법감시부", "when": "8월" }
  ]
}
```
- **최대 4개**.

## 슬라이드 구성 원칙 (임원 보고용)

- **총 10~14장.** 표지·목차·마무리 제외하면 본문 8~11장.
- **첫 본문 슬라이드는 항상 "결론 먼저"** — 임원은 3장까지만 본다는 전제로 쓴다.
- 보고서(읽는 글)와 슬라이드(보는 글)는 문법이 다르다. **보고서 문장을 그대로 붙여넣지 않는다.**
  - 보고서: "…에 따라 우리 기관은 인증 체계를 재설계할 필요가 있는 것으로 판단된다."
  - 슬라이드: "인증 체계 재설계 불가피 — 18개월 소요"
- 슬라이드 제목은 **주장**이어야 한다. "현황"(X) → "대응 착수 없으면 시행일 미준수"(O)
- 숫자가 있으면 `chart`, 비교면 `table`, 나머지는 `bullets`. **전부 bullets로만 채우지 않는다.**
- **보고서에 없는 숫자·조항을 지어내지 않는다.** 근거가 없으면 그 슬라이드를 빼는 게 낫다.

## 권장 뼈대

| # | 타입 | 내용 |
|---|---|---|
| 1 | (표지) | 제목·부제·일자 — `title`/`subtitle` 로 자동 생성 |
| 2 | bullets | **핵심 결론 3줄** (여기서 승부) |
| 3 | bullets | 사안 요약 (무엇이·언제부터·누구에게) |
| 4 | table | 관련 법령·규정 매핑 |
| 5~7 | bullets/chart | 우리 기관 영향 (사업·시스템·데이터·조직) |
| 8 | bullets | 리스크 & 컴플라이언스 체크포인트 |
| 9 | chart/table | 실행 과제 (우선순위·비용) |
| 10 | timeline | 대응 로드맵 |
| 11 | action | 즉시 액션 Top 3 |
