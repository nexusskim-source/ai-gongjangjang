# 사장님 대시보드 — 연결한 데이터 소스 목록

- **앱**: 달콤 베이커리 디저트 쇼핑몰 (https://dessert-shop-rouge.vercel.app)
- **화면**: 사장님(admin) 전용 대시보드
- **작성일**: 2026-07-14
- **기준일(데이터가 있는 최근 영업일)**: 2026-07-12

대시보드는 **Supabase(PostgreSQL) 테이블 7개 + 외부 API 2개**를 읽는다.
집계 SQL과 API 호출은 전부 `admin.js` 한 파일에 모여 있고, 로컬 서버(`server.js`)와 배포용 서버리스 함수(`api/admin/*.js`)가 이 파일을 함께 쓴다.

---

## 1. Supabase — 카페 운영 DB (`cafe_*`)

week_5 퀘스트6에서 내가 직접 적재한 Day On(데이온) 카페의 **90일치 운영 데이터**다.
대시보드의 매출·메뉴·리뷰·재고 숫자는 전부 여기서 나온다.

| 테이블 | 행수 | 사용하는 위젯 | 읽는 값 |
|---|---:|---|---|
| `cafe_daily_sales` | 90 | KPI 4칸, 이번 주 매출 | 일별 매출, 손님 수, 주문 건수, 날씨, 휴무 여부 |
| `cafe_menu_sales` | 1,392 | 인기 메뉴 TOP3 | 일자 × 메뉴 판매량·판매금액 (최근 7일 합산) |
| `cafe_menus` | 16 | 인기 메뉴 TOP3 | 메뉴명, 카테고리 (판매량 집계에 조인) |
| `cafe_reviews` | 60 | 리뷰 평점 KPI, 최근 리뷰 | 별점, 출처(네이버/카카오맵 등), 메뉴, 리뷰 원문 |
| `cafe_inventory` | 20 | 발주 필요 재고 | 현재고, 안전재고, 단위, 거래처 |

### 위젯별 집계 방식

| 위젯 | 집계 |
|---|---|
| 최근 영업일 매출 | 최근 영업일 매출 + 직전 영업일 대비 증감률 |
| 손님 수 / 객단가 | 최근 영업일 손님 수, 매출 ÷ 주문 건수 |
| 리뷰 평점 | 최근 30일 리뷰 평균 별점 |
| 이번 주 매출 | 기준일이 속한 주(월~일) 일별 매출 + 지난주 합계 대비 증감률 |
| 인기 메뉴 TOP3 | 최근 7일 판매량(qty) 상위 3개 |
| 발주 필요 재고 | `current_stock <= safety_stock` 인 품목 (부족률 순) |
| 최근 리뷰 | 최근 3건 |

### 아직 위젯에 안 붙인 테이블

DB에는 있지만 이번 대시보드에서는 사용하지 않았다. (위젯 추가 시 바로 활용 가능)

| 테이블 | 행수 | 들어있는 것 |
|---|---:|---|
| `cafe_purchase_orders` | 268 | 발주 이력 (발주일, 수량, 금액, 입고완료/배송중/발주요청) |
| `cafe_visitors` | 90 | 일자별 매장/테이크아웃 손님 수, 피크 시간대 |

## 2. Supabase — 쇼핑몰 앱 테이블 (`shop_*`)

| 테이블 | 행수 | 용도 |
|---|---:|---|
| `shop_admin_todos` | 3 | **오늘 할 일** 체크리스트. 이번 퀘스트에서 새로 만든 테이블 (체크/추가/삭제가 여기에 저장) |
| `shop_users` | 14 | 로그인 + **매 요청마다 admin 권한 재확인** (토큰에 적힌 이름만 믿지 않는다) |

> 이 Supabase 는 여러 앱이 공유하므로, 이 앱은 `shop_*` 전용 테이블만 쓰고 다른 앱 테이블은 건드리지 않는다.

## 3. 외부 API

### Open-Meteo (날씨 예보) — API 키 불필요

- **엔드포인트**: `https://api.open-meteo.com/v1/forecast`
- **좌표**: 위도 37.5686, 경도 126.9282 (서울 연희동 — 우리 카페 위치)
- **가져오는 값**: 오늘 날씨 상태, 최저/최고 기온, 강수확률
- **쓰는 곳**: AI 브리핑 하단 배지 + 브리핑 문장의 근거
  (예: `오늘 강한 비 · 25~31.5℃ · 강수 100%`)
- 호출이 실패해도 브리핑은 그대로 진행된다.

### OpenAI `gpt-4o-mini` (AI 브리핑 생성)

`POST /api/admin/briefing` 이 아래 8가지를 텍스트로 묶어 넘기고, 사장님이 아침에 30초 안에 읽을 3~4문장을 받는다.

1. 최근 영업일 매출·손님 수·주문 건수·객단가 + 직전 영업일 대비 증감
2. 이번 주 매출 합계, 지난주 대비 증감, 요일별 매출
3. 최근 7일 인기 메뉴 판매량
4. 최근 30일 리뷰 평균 별점 + 최근 리뷰 원문
5. 안전재고 이하 발주 필요 품목
6. **날씨별 하루 평균 매출** (비 오는 날 매출이 얼마나 빠지는지 근거로 삼으라고 함께 넘김)
7. 오늘 연희동 날씨 예보 (Open-Meteo)
8. 사장님의 할 일 목록

프롬프트 규칙: 데이터에 있는 숫자만 인용(지어내기 금지), 마지막 문장은 **오늘 당장 실행할 액션 1가지**.
OpenAI 키가 없거나 호출이 실패하면 규칙 기반 브리핑으로 자동 대체된다.

**실제 생성 결과 (2026-07-14)**

> 지난 영업일인 7월 12일 매출은 592,400원이었으며, 손님 수는 83명으로 직전 영업일 대비 -34.6% 감소했습니다.
> 최근 7일 동안 가장 인기 있는 메뉴는 너츠라떼로 85개가 판매되었고, 평균 별점은 4.48점입니다.
> 오늘 비가 강하게 내릴 것으로 예상되니, 인기 메뉴인 너츠라떼와 함께 바질 페스토와 리코타 치즈 발주를 서둘러 진행해 주시기 바랍니다. ☔

## 5. 환경변수 (데이터 소스 접속 정보)

| 변수 | 용도 |
|---|---|
| `DATABASE_URL` | Supabase PostgreSQL 연결 (cafe_*, shop_*) |
| `JWT_SECRET` | 로그인 토큰 서명 |
| `OPENAI_API_KEY` | AI 브리핑 생성 |

Open-Meteo 는 키가 필요 없다. 실제 값은 `.env`(로컬)와 Vercel 프로젝트 환경변수에만 두고 깃에는 올리지 않는다.
