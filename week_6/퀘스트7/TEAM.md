## Part 1. 자동화할 '실제 업무'

> **매주 반복되는 규제·디지털 기사 검토를, 보고서(워드)와 임원 보고용 PPT까지 한 번에 뽑아내기**

| 항목 | 내용 |
|---|---|
| 업무 | 금융 규제·감독·보안·AI·클라우드 관련 기사가 뜨면, DT본부장 관점으로 검토하고 이사회·임원 보고 자료를 만든다 |
| 반복 주기 | **주 1~3회** (규제 이슈는 계속 나온다) |
| 지금 방식 | 기사 읽기 → 관련 법령·감독규정 원문 찾아 다운로드 → 우리 기관 영향 분석 → 워드 보고서 → **PPT는 손으로 다시 제작** |
| 걸리는 시간 | 건당 3~4시간 (그중 PPT 재작업이 1시간 이상) |
| 자동화 가치 | 리서치·초안·슬라이드는 기계가 하고, 나는 **판단과 승인**만 한다 |

**이미 있는 자산**
- `.claude/skills/dt-regulation-brief` — 기사 판별 → 원문 다운로드 → Opus 보고서 → 워드 변환 (리서처+분석가 역할을 한 몸에 갖고 있음)
- `week_6/퀘스트3/make_ppt.py` — python-pptx 로 네이티브 차트 PPT 생성 (브랜드 컬러·차트 코드 재사용 가능)

**이번에 새로 붙이는 것**: 보고서 → **임원 보고용 PPT** 자동 생성, 그리고 **검수자**.

## Part 2. 에이전트 팀 편성표 (4명)

| 에이전트 | 역할 (한 문장) | 참조 컨텍스트 (파일·폴더·MCP) | 도구 |
|---|---|---|---|
| **리서처** | 기사를 읽고, 관련 법령·감독규정·가이드라인 **원문을 찾아 내려받는다** | `skills/dt-regulation-brief/references/korea-financial-sources.md` | WebFetch, WebSearch, `scripts/download_files.py` |
| **분석가** (Opus) | 원문을 근거로 **DT본부장 관점 8섹션 보고서**를 쓴다 | `research.md`, 다운로드된 원문 PDF, 보고서 템플릿(SKILL.md) | Read, Write |
| **검수자** | 보고서의 **법령 조항·숫자를 원문과 대조**해 지어낸 내용을 잡아낸다 | `report.md`, 다운로드된 원문 PDF | Read, Grep |
| **슬라이드 디자이너** | 보고서를 **임원 보고용 PPT 12장**으로 만든다 | `report_final.md`, `ppt-style.md`(브랜드 규칙), `render_ppt.py` | Read, Write, Bash(py -3) |

### 왜 이렇게 나눴나

- **리서처와 분석가를 나눈 이유** — 자료 수집(넓게 훑기)과 분석(깊게 파기)은 요구되는 사고가 다르다. 섞으면 자료 찾다가 지쳐 분석이 얕아진다.
- **검수자를 분석가와 분리한 이유** — 규제 보고서의 최대 리스크는 **없는 조항을 그럴듯하게 지어내는 것**이다. 자기가 쓴 글은 자기가 못 잡는다. 반드시 다른 눈이 원문과 대조해야 한다.
- **슬라이드 디자이너를 따로 둔 이유** — 보고서(읽는 글)와 슬라이드(보는 글)는 문법이 다르다. 보고서를 그대로 붙여넣은 PPT는 임원 보고에서 안 통한다.

## Part 3. 워크플로우 (핸드오프)

한 사람의 **결과물 파일**이 다음 사람의 **입력**이 된다. 산출물은 전부
`C:\수경_에이전트파일다운\<기사제목>_<YYYYMMDD>\` 한 폴더에 모인다.

```
        [공장장] 기사 URL 투입
              │
              ▼
      ┌───────────────┐
      │  ① 리서처      │  기사 읽기 + 관련 법령·가이드 원문 검색
      └───────┬───────┘
              │  research.md  +  받을 자료 목록
              ▼
        ★ 승인 ①  "이 자료들 받을까요?"  ← 공장장 개입 (내 디스크에 파일을 쓰므로)
              │
              ▼  (승인된 원문 PDF/HWP 다운로드)
      ┌───────────────┐
      │  ② 분석가      │  우리 기관 영향·리스크·실행과제 분석
      │   (Opus)      │
      └───────┬───────┘
              │  report.md  (8섹션 초안)
              ▼
        ★ 승인 ②  "이 방향으로 쓸까요? 독자는 이사회?"  ← 공장장 개입 (방향이 틀리면 전부 헛수고)
              │
              ▼
      ┌───────────────┐
      │  ③ 검수자      │  조항·숫자를 원문과 대조 → 오류 지적
      └───────┬───────┘
              │  review.md  →  분석가가 반영  →  report_final.md  →  📄 보고서.docx
              ▼
      ┌───────────────┐
      │  ④ 슬라이드    │  보고서를 12장 슬라이드로 구조화
      │    디자이너    │
      └───────┬───────┘
              │  slides.json  (슬라이드별 제목·불릿·차트 데이터)
              ▼
        ★ 승인 ③  "이 목차로 PPT 뽑을까요?"  ← 공장장 개입 (렌더 전 목차 확인)
              │
              ▼
        render_ppt.py  →  📊 보고서.pptx
              │
              ▼
        [공장장] 최종 검토 후 이사회 보고
```

### 핸드오프 계약 (파일)

| 단계 | 넘기는 파일 | 받는 사람 |
|---|---|---|
| 리서처 → 분석가 | `research.md` + 원문 PDF들 | 분석가 |
| 분석가 → 검수자 | `report.md` | 검수자 |
| 검수자 → 분석가 | `review.md` (지적사항) | 분석가 (반영 후 `report_final.md`) |
| 분석가 → 슬라이드 | `report_final.md` | 슬라이드 디자이너 |
| 슬라이드 → 렌더러 | `slides.json` | `render_ppt.py` |

**⚠️ 기존 스킬 수정 필요**: 현재 `dt-regulation-brief` 는 워드 변환 후 원본 `.md` 를 **삭제**한다(A-8).
그러면 슬라이드 디자이너가 읽을 게 없다. **`report_final.md` 를 남기도록 고쳐야** 이 워크플로우가 성립한다.

### 공장장(나)이 개입하는 3지점

| 게이트 | 무엇을 승인하나 | 왜 여기서 |
|---|---|---|
| ★① 다운로드 목록 | 어떤 법령·규정 원문을 받을지 | 내 디스크에 파일을 쓰는 일 (되돌리기 번거로움) |
| ★② 보고서 방향 | 관점·강조점·독자(이사회/실무) | 방향이 틀리면 Opus 작업이 통째로 헛수고 |
| ★③ 슬라이드 목차 | 12장 제목 구성 | 렌더 전에 목차만 보면 5초면 판단 가능 |

나머지(검색·다운로드·집필·검수·렌더)는 **전부 자동**. 나는 3번만 "예/아니오" 하면 된다.

## Part 4. 실제로 만들 팀원 1명 → **슬라이드 디자이너**

| 왜 이 팀원인가 | |
|---|---|
| 리서처·분석가 | 이미 `dt-regulation-brief` 스킬 안에 구현돼 있다 (새로 만들 게 없음) |
| 검수자 | 만들기는 쉽지만 결과물이 눈에 안 보인다 |
| **슬라이드 디자이너** | **유일하게 새로 생기는 능력**이고, 결과물(PPT)이 즉시 보이며, `make_ppt.py` 라는 검증된 코드가 있어 성공 확률이 높다 |

**설계 원칙: LLM이 .pptx 를 직접 그리게 하지 않는다.**
에이전트는 `slides.json`(구조화된 스펙)까지만 쓰고, 실제 렌더링은 `render_ppt.py`(python-pptx)가 한다.
→ 매번 같은 품질의 슬라이드가 나오고, 브랜드 컬러·차트 코드를 재사용할 수 있다.

```
report_final.md  →  [슬라이드 디자이너]  →  slides.json  →  render_ppt.py  →  보고서.pptx
                     (무엇을 말할지)                          (어떻게 보일지)
```

### 기존 스킬 수정 사항

`dt-regulation-brief` 를 이 워크플로우에 맞게 고쳤다.

- **A-8**: 워드 변환 후 `.md` 를 삭제하던 것을 **삭제 금지**로 변경 (PPT의 입력이므로)
- **A-9 신설**: 보고서 후 "PPT도 만들까요?" → `slides.json` → **★승인 게이트 ③(목차 확인)** → 렌더
- 승인 지점이 ①다운로드 목록 ②보고서 방향 ③슬라이드 목차 **3곳**으로 명확해짐

### 검증 결과

샘플 `slides.json`(5종 타입 전부 포함)으로 렌더 → **7장 생성**(표지 + 본문 5 + 마무리),
PowerPoint 네이티브 차트 정상(COLUMN, 시리즈 1개), 표 4×3 정상, **슬라이드 경계 초과 0건**.
