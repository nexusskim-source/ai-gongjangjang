# 회고 — 여기어때(내 주변 맛집·카페 발견)

**잘 된 점.** 로컬 실행(`server.js`)과 Vercel 서버리스(`api/[...path].js`)가 **`core.js` 한 벌을 공유**하도록 설계한 게 가장 주효했다. 덕분에 로직 중복 없이 두 환경이 똑같이 동작했고, 배포 후에도 "로컬에선 되는데 배포에선 안 되는" 문제를 로직 차원에선 겪지 않았다. 기능적으로도 구글 Places의 **실시간 평점·영업정보에 수요미식회·식객 방송 맛집 큐레이션을 얹어** 단순 지도앱과 차별화했고, 위치 기반 자동 추천 → 상황·취향 필터 → 목록/지도 전환 → 상세·저장·공유까지 실제 사용자가 "오늘 어디 갈까"를 해결하는 흐름을 한 화면에서 끝까지 완성했다. 빌드 도구 없이 단일 `index.html`(React CDN)로 유지해 가볍게 배포·수정할 수 있었던 것도 만족스럽다.

**아쉬운 점.** 배포에서 Vercel이 프로젝트를 Node 앱으로 오탐지해 **정적 루트(`/`)가 404**가 났고, `vercel.json`을 명시적 빌드(`@vercel/static` + `@vercel/node`)로 바꾸고 나서야 해결됐다 — 배포 구조를 처음부터 명시했다면 겪지 않았을 시행착오다. 또 Babel을 브라우저에서 컴파일하는 방식이라 **첫 페인트가 2~3초 지연**돼(데모 도입부가 잠깐 흰 화면) 사전 번들/프리컴파일을 도입할 여지가 있다. 저장(찜)이 브라우저 로컬 상태라 새로고침·기기 간에 유지되지 않는 점, 구글 API 호출 비용·쿼터와 큐레이션 좌표 캐시 갱신을 자동화하지 못한 점도 다음에 보완할 숙제로 남았다.
